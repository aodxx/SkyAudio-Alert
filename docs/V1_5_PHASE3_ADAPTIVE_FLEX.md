# V1.5 Phase 3 — Adaptive Flex Carousel\n\n## Status\nPhase 3 implementation complete on its feature branch. Production remains **NO-GO** until review and acceptance gates are completed.\n\n## Goal\nReplace the single long Flex bubble with a short, horizontal carousel that follows the V1.5 visual contract.\n\n## Runtime rules\n- Card 1 is always flood-first, self-contained, and immediately understandable.\n- Card count is dynamic; the renderer does not force a fixed four-card layout.\n- Five verified severity states are supported: normal, watch, affected, critical, unknown.\n- Critical action is visible on Card 1; critical source/verification remains available on a later card.\n- Unknown explicitly communicates uncertainty and never uses normal-looking severity treatment.\n- Stale is shown as a freshness condition and does not silently replace severity.\n- Weather supports the flood report; it never establishes actual flooding.\n- Approved CTAs only: CCTV, flood source, weather/radar.\n- Severity is communicated by text/labels as well as color.\n- Carousel is capped at 10 bubbles for payload safety.\n- Planner cards are presentation data; verified flood severity remains the source of truth.\n\n## Compatibility\nIf a PresentationPlan is not present yet, the renderer builds deterministic state-specific cards from the existing report data. This lets Phase 3 land before full planner runtime wiring.\n\n## Acceptance\n- Five severity states render as a carousel.\n- Card 1 contains the severity/uncertainty signal.\n- Critical action appears immediately.\n- Unknown uncertainty is explicit.\n- Flood-first ordering is preserved.\n- No market/news content is introduced.\n

> **Reopened by V1.6 (2026-10-04):** acceptance for this phase did not cover visual hierarchy or the audio requirement. Superseded in part by Decision 022; see `docs/REVIEW_V1_6_PRESENTATION_REDESIGN.md`.
