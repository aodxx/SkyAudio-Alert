# Medium-Length Audio (3–5 Minutes) Implementation Plan

> **For agentic workers:** Execute inline in this session; the user has approved the target audio format. Use a failing test before each behavior change.

**Goal:** Replace the repetitive 10-minute narration pipeline with a fact-safe, non-repetitive 3–5 minute Thai report and ensure audio failures do not suppress the Flex alert.

**Architecture:** Generate four distinct topical narration sections from the existing verified flood/weather context, join them into one script, and synthesize once. Measure the resulting MP3 duration with `ffprobe`; deliver Audio only when duration is within 180–300 seconds. If narration/TTS/audio validation/storage fails, record an `audio.withheld` degraded stage and still deliver the valid Flex alone; expose partial failure clearly in the workflow status.

**Tech Stack:** Node.js, existing Gemini Content and Gemini TTS APIs, FFmpeg/ffprobe, Node built-in test runner, GitHub Actions.

**Spec:** User-selected “ปานกลาง: 3–5 นาที มีรายละเอียดเพิ่ม แต่ไม่ทวนซ้ำ”; authoritative safety and flood-first requirements in `PRD.md` and `DECISIONS.md`.

## Global Constraints

- Use only verified flood/weather facts; forecasts must not assert that flooding occurred.
- Retain deterministic safety validation before TTS.
- Target actual audio duration inclusively: 180,000–300,000 ms; files remain under 16 MiB.
- Do not pad audio with repeated explanations to satisfy duration. If generated/fallback audio is outside range, withhold Audio and keep Flex deliverable.
- Keep Gemini TTS as production default and preserve current voice-profile configuration.
- Do not send to LINE or run production acceptance as part of this implementation; production remains NO-GO.
