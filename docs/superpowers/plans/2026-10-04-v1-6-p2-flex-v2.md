# V1.6 P2 Flex v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Render LINE Flex from verified `FactsSnapshot` + `VisualPlan`, enforce structural/text/payload budgets before TTS or delivery, and remove the legacy score/fallback renderer.

**Architecture:** Keep weather analysis and the current audio/TTS path unchanged for P2. Make adapter severity canonical inside the presentation contract (never request severity from Gemini), then build the Flex carousel only from P1 fact IDs and typed visual slots. A deterministic renderer selects state-specific card order/structures, and a fail-closed linter checks the serialized LINE message before the pipeline can proceed.

**Tech Stack:** Node.js 20+, CommonJS, `node:test`, LINE Flex JSON, built-in `crypto`/`fs` only; no new runtime dependencies.

**Spec:** `REVIEW_V1_6_PRESENTATION_REDESIGN.md` §§F, G1–G4, J2; Decision 022.

## Global Constraints

- Flood severity comes only from the flood adapter; it is not requested in Gemini's response schema.
- Every dynamic name, number, timestamp, station, location, and weather value rendered on screen must resolve to a `FactsSnapshot` fact ID.
- `unknown` remains visibly uncertain; stale freshness never changes severity.
- Use only the three allow-listed CTA URLs already documented in the spec and source.
- Every bubble uses `kilo`; carousel ≤ 12 bubbles; serialized payload < 50 KB; alt text ≤ 400 characters.
- Reject over-budget output; never silently truncate a claim or add a placeholder for absent source data.
- This phase does not change TTS/audio duration, scheduling, credentials, or production deployment; explainers remain pending community review and production scheduling remains NO-GO.
